# 科研论文图片自动绘制 Skill（中文）

## 核心目标

你不是在把代码“翻译成流程图”，而是在把**真实方法**组织成一张适合论文发表的科研图片。

遵循优先级：

**科学准确性 > 关键机制完整性 > 可读性 > 视觉简洁 > 装饰性**

## 默认输入

- `project_root`：项目根目录；如未指定，使用当前工作目录。
- `references_dir`：默认 `<project_root>/papers`。
- `output_dir`：默认 `<project_root>/figure`，不存在则创建。
- `focus`：优先关注 LLM harness、推理流程和训练流程；若不存在，则改为项目中最核心的方法模块。
- `languages`：默认输出中文与英文两个版本。

尊重用户明确指定的路径、模块重点和输出格式；当项目结构不完整、路径不可用或缺少参考论文时，要明确说明限制，而不是假装已经读取。

## 1. 阅读实现，建立证据

先读取 README、入口脚本、核心模块、配置、训练代码，以及必要的测试、日志或样例；只进行理解与绘图所需的检查，不擅自运行完整训练或修改业务代码。

重点确认：

- 系统的真实输入 / 输出是什么
- LLM harness 是否存在，以及其上下文构造、模型调用、动作解析、工具 / 环境执行、反馈、校验和终止条件
- 训练流程是否存在，以及数据来源、预处理、监督或奖励信号、损失目标、参数更新方式、训练后如何参与推理
- 哪些模块是方法贡献，哪些只是普通工程组件

为关键模块、关键连线和关键公式建立简短证据记录，例如：`文件路径:函数/类/配置项`。区分“代码确认”“文档描述”“合理推断”；未确认机制不要作为既成事实画进图里。

## 2. 学习参考论文的视觉语言

优先查看 `references_dir` 中相关论文的 overview / method / system figure，并记录要借鉴的内容：

- 整体布局
- 信息层次
- 文字密度
- 配色与线条风格
- 模块图标 / 隐喻表达
- 公式放置位置
- 重点模块的强调方式

借鉴的是**设计语言**，不是参考论文的方法内容，也不是逐图照搬。

## 3. 确定图的主线叙事

先用一两句话概括整个方法，然后明确：

1. 方法最重要的 1–3 个贡献点；
2. 不可丢失的关键信息；
3. 哪些模块需要展开，哪些只需概括。

按三层组织信息：

- **全局层**：整体方法框架
- **机制层**：最重要的 1–2 个核心模块
- **细节层**：必要的公式、打分函数、目标函数、关键中间表示或微型示例

删除冗余工程细节、重复标签和大段说明，但不要删除真正区分该方法的机制。

## 4. 绘制 ACL / EMNLP 风格的科研图片

目标风格：

- 简洁、清晰、可读
- 低文字密度
- 不像普通业务流程图
- 更像论文中的 scientific illustration
- 每个小模块尽量采用简洁漫画式 / 插画式表达
- 整体可加入克制的手绘感

推荐做法：

- 用空间分区表达阶段，而不是把所有内容放进同样大小的方框
- 用小图标、对象交互、状态卡片、轨迹片段等方式替代过度文字解释
- 只保留真正必要的数据流、控制流或参数更新箭头
- 对核心贡献模块做明显强调：更大空间、更醒目的边界或更明确的视觉聚焦
- 保持背景简洁、配色克制、留白充足

注意：手绘感只能作为增强自然感的辅助风格，不能影响公式、标签、箭头和整体逻辑的清晰度。

## 5. 在重点模块中保留必要公式与计算

只在真正关键的模块旁边加入必要的论文细节，例如：

- 核心评分函数
- 目标函数
- 聚合关系
- 策略更新关系
- 关键中间变量

原则：

- 公式服务于解释重点，不要平均分配给所有模块
- 保证符号与实现一致
- 缺乏证据时宁愿使用准确文字描述，也不要凭空编造公式
- 训练信号、执行反馈与参数更新关系不能混淆

## 6. 双语输出与可编辑交付

默认生成：

- `overview_en.pdf`、`overview_zh.pdf`
- `overview_en.svg`、`overview_zh.svg`
- `overview_en.png`、`overview_zh.png`
- `src/`：脚本、源图、标签表或导出说明
- `README.md`：记录方法概述、代码证据、参考风格、保留细节和导出步骤

两种语言应尽量共享：

- 布局
- 模块编号
- 颜色
- 图标
- 箭头
- 数学符号

允许为了排版对标签长度做小幅调整，但不要改变结构和信息量。

## 7. 检查与迭代

至少检查三类问题：

1. **科学内容**：是否与代码证据一致；是否误加或漏掉关键模块；
2. **视觉表达**：是否简洁、清晰、有重点；是否降低了流程图感；
3. **导出质量**：中英版本是否一致；字体是否正常；PDF / SVG / PNG 是否可用。

用户常见反馈的处理方式：

- “太像流程图”：改变构图与模块表达，减少机械方框，不删掉必要逻辑。
- “文字太多”：压缩标签、改用图示或图注，但不要删掉核心机制。
- “细节丢了”：在重点模块恢复公式、关键计算或中间表示，不要把整张图重新塞满。
- “再自然一点”：增强轻手绘轮廓与装饰，但保持科学可读性。

## 8. 最终交付说明

最终请给出：

- 实际生成文件路径
- 图的主线叙事
- 重点突出模块
- 保留的核心公式 / 计算
- 已完成的检查项
- 仍需人工微调的地方
